Why not just use SAP S/4HANA?
Why do we need a Data Lake?

At first, it sounds like SAP should be enough. It already stores business data, so why introduce another platform? The answer is simple: SAP S/4HANA is built to run the business. A Data Lake is built to unlock the value of the business data.

The Difference

SAP S/4HANA is an ERP system designed for day-to-day operations such as sales, finance, procurement, inventory, and other business transactions. A Data Lake, on the other hand, is designed for analytics, AI, and advanced reporting. It combines data not only from SAP but also from CRM systems, websites, mobile applications, IoT devices, and many other sources.

Business Value
"If tomorrow the CEO asks: 'Show me how website activity affects vehicle sales and customer service.' SAP alone cannot easily answer that because not all of this data exists inside SAP. A Data Lake brings all these data sources together into one place, making it possible to generate insights, build AI models, and support better business decisions."

SAP S/4HANA runs the business.
A Data Lake helps the business learn, predict, and innovate.

That's why we use both — but when it comes to analytics and AI, the Data Lake is the right foundation.

Implementation Options

Two Ways to Move SAP Data to AWS

Same destination, two different paths — here's how they compare.

Option 2

SAP Datasphere (POI)

Concept
SAP Datasphere acts as a "pipe," not a storage destination — data passes straight through to AWS S3 without being persisted inside Datasphere.
Benefit
No additional storage cost inside SAP, and governance happens at the source (via CDS Views).
Cost
Billed based on the volume of data transferred (Premium Outbound Integration) — the less data moved, the lower the cost.
Best when
You want a fully SAP-managed solution with minimal added complexity.
Option 3

OData-Based Extraction

Concept
Uses the standard OData protocol (SAP Gateway/SEGW) to extract data without any direct database access.
Benefit
Uses existing standard SAP technology (SAP Gateway) — nothing new to purchase, and the connection is secured via SAP Cloud Connector.
Cost
No extra transfer fees; relies on an AWS Glue ETL Job to pull the data.
Best when
You want a secure, simple solution without additional middle layers (non-invasive).
